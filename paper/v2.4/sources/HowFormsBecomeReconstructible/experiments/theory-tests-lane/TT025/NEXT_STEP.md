# Next: vary the writing window while body repair continues

Draft proposed after inspecting verified TT025 results. This is development
design, not a frozen registration, implemented experiment or launched job.

The first complete corrected informative rewrite already loses 3.223 points
of fresh-recipient recognition; all eight observed cycle means are negative.
The next question is therefore whether continued writing within a repair
episode causes avoidable loss. A shorter window might help, but TT025 supplies
no winning budget and its saved checkpoints cannot locate the relevant time.

Use a bounded one-episode intervention before another serial confirmation.
Restore the same incoming packet and actually injured body into every variant.
Allow the body, memory and feedback to evolve for the full 1,000 repair updates
in every variant. Permit record writing only during the first **0, 1, 10, 100
or 1,000 updates**, using the same native writing rate while enabled. After
the window, hold the record byte-exact while body repair continues. These are
simple fixed duration probes, chosen after TT025; none is claimed optimal.

Retain all first-episode cases from the four exposed source blocks, all 16
message/replicate positions, all four historical futures and both families.
There are 32 native body contexts before branching. The first episode is
chosen to isolate the initial rewrite before histories diverge, because TT025
already measures harm there. Do not select cases by body pass/fail, geometry,
injury stratum or receiving outcome. The eight-cycle TT025 evidence remains
available in full; a first-episode result will not establish later durability.

The five duration variants use the same fill-corrected memory initializer.
Include full-capture and zero-initial-memory controls with 1,000 writing
updates. The zero-writing corrected-memory variant preserves the incoming
record while controlling the memory initializer for its own body comparison.
Its packet can share an assay with the initial packet after byte verification,
but its repaired-body outcome cannot be copied from a different initializer.
Retain the supplied injury mask as an explicit resource.

Pair birth/injury/repair randomness within each historical context. Do not
substitute another variant's later body or memory state after writing causes
the trajectories to diverge. This must be an actual interrupted-writing
intervention, not interpolation between saved records. If existing full-budget
trajectories are reused, require exact state, parameter, stream and native
replay provenance before any reuse.

Compare each outgoing packet with its incoming packet using four new fresh
recipient draws, paired across durations and controls. Specify a new random
namespace, all phase seeds and checked separation before acquisition. Keep
the finite channel at 256 float64 entries / 2,048 bytes; body state, memory,
injury mask and task labels do not enter the receiving dynamics. Use the same
1,000-update reader and scoring convention as TT025.

The principal descriptive result is the complete informative corrected
duration-versus-paired-effect curve. Report every duration's absolute incoming
and outgoing recognition, block effects and paired gains, harms and ties,
with common records and both full-budget controls alongside it. Keep repaired
body performance separate. Include all prespecified message, injury and
historical body-status strata without using them to choose enrollment or an
after-the-fact winning policy. There is no significance or confirmation gate.

Moving closer to preservation as the writing window shrinks would establish
less measured damage, not a benefit of overwriting an already useful record.
An observed advantage over the 1,000-update writer alone is insufficient to
claim a reason to write. If all nonzero budgets lose to preservation, retain
that negative result. A favorable exposed-case budget would require a later
frozen test on genuinely new starting cases before a population claim; serial
body performance would still require its own actual continued trajectories.

Before acquisition, implement the gate and independent reference, qualify
zero/full-budget identities and exact post-gate packet preservation, and
benchmark excluded cases at full duration. Freeze the schedule, endpoints,
reuse rules, runtime forecast and storage limit before new outcomes. Use two
single-thread workers within the shared CPU budget. Any run forecast above
ten minutes must be detached, with one acknowledgment and no automatic polling,
retry, extension or successor. No new native simulation was run to write
this proposal.
