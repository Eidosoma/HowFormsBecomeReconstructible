# E034 — does longer settling improve the next rebuilt record?

Authorized by the user's 27 September “lets go” following E033 and its lead
review. E033 improved expression from unchanged packets; test whether the same
delay improves outgoing records when used during rebuilding. This is a post hoc
intervention on all 32 saved E031 blocks (27000–27031), 512 candidate lineages,
without selection by success. It is not fresh replication or a serial-policy
qualification.

## Fixed comparison

Start with each maturing-policy outgoing packet after generation eight.
Reconstruct its generation-nine damaged renewal with two receiving schedules:
256 settling / 2048 total steps (original) and 1024 / 2048 (delayed). Both use
local-strength normalization, identical birth/noise streams, the same 24-cell
injury, both cues, immediate body-only capture, and the unchanged >0.5
preserve-strong/refresh-weak rule. No new teaching, ancestry labels or desired
output labels enter either renewal. Strong survivors are copied explicitly;
weak available weights are refreshed from current-body activity. Holding
dynamics and all remaining parameters are unchanged. No other delay is searched.

The original branch must reproduce E031 generation nine's retained candidate
outgoing bytes, masks, retained/eligible edges, body means and every holding
digest exactly. Source arrays committed but not retained remain governed by
E031's already completed independent replay.

Test both outgoing records in a crossed terminal assay: original and delayed
settling (256/2048 versus 1024/2048), both fixed-four and normalized receivers,
all seven own/foreign/shuffled/erased/untrained/communication-off/source-cut
arms and all three injuries. All assay randomness is paired using the unchanged
E022 horizon-nine streams. Every panel uses the same total step count. Retain
172,032 individual-cue terminal scores and 2,048 current-body scores.

The single focal endpoint is **delayed-renewal minus original-renewal both-cue
success**, with the SAME **delayed normalized terminal receiver**, own packet
and scattered terminal injury. Its two-sided 95% whole-block bootstrap lower
bound must exceed **five percentage points** for
`SETTLED_REBUILDING_BENEFIT_ESTABLISHED`. Five points is the meaningful gain
requirement for this one-boundary intervention, distinct from E033's ten-point
receiving comparison. Report absolute reliability (lower bound above 75%)
separately. Neither relative improvement nor one-step reliability establishes
long-term maintenance.

Report the rebuilding contrast under both terminal schedules/readers, the
terminal-delay contrast within each rebuilding branch, and their interaction.
Report body both-cue success, accuracy and margin; terminal equivalents;
original 24 context gates and absolute performance for every panel. All
secondary intervals and gates are pointwise. Use 10,000 whole-block bootstrap
draws with namespace ["E034", "bootstrap", "settled_rebuilding"]. Keep all
blocks, scores, margins and output means; do not choose the endpoint by results.
