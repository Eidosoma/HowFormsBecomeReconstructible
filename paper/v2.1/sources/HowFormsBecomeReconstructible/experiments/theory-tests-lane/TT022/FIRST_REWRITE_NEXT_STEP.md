# Proposed counterfactual: separate replacement fill, feedback and writing

Prepared after TT022 and its first-rewrite diagnostic. This is an exposed-case
mechanism experiment proposal, not a registration, launched run or fresh
confirmation. It addresses the large first-episode loss and injury-polarity
pattern; it does not tune a serial policy from those same outcomes.

Restore each saved first injured body and incoming captured packet from all
four TT022 blocks, four futures and both families. Preserve all sixteen case
positions and failed bodies. Keep V0, zero ema, incoming theta, tissue parameters
and the original phase-specific random environment identical across variants.
Only the initialization of R and the writing switch vary. The task label is
available for offline scoring only.

| Initial memory | Writing on | Writing off |
| --- | --- | --- |
| Full injured capture: R0 = V0 | Existing repeated-capture condition | Isolate feedback with packet preserved |
| Subtract nominal replacement fill: R0 = V0 − resting × fresh_mask | Test fill contribution with writing | Test fill contribution through body feedback |
| Zero R0 | Same-packet ordinary writing | Existing one-time-capture continuation |

The subtraction changes only memory at fresh cells, leaving their actual V0
at the original negative resting state plus jitter. It retains the original
jitter in R0 and changes no target label, teacher, parental body or incoming
packet. The full-capture and zero-memory controls distinguish removal of the
fill component from discarding all surviving-body information. Neither the
meaning of the task nor the positive/negative injury stratum may select a
variant online.

The fresh-cell mask is additional intervention information. Give all variants
the same declared experimental inputs and disclose which ones use the mask.
A favorable result would support an engineered correction under this supplied
resource, not an equal-information superiority claim for the original rule or
autonomous recognition of injury. Do not call the resting fill itself a bug.

Run one repair episode under unchanged physics, then score its outgoing packet
in the same generation-two receiving environment as TT022. Writing-off outputs
must remain byte-identical to the starting packet, so their receiving read
can reuse the checked one-time control with exact packet/environment bindings.
The existing full-capture writing-on and zero-memory writing-off trajectories
can also be retained without recomputation. There are four new repair arms
and two new receiving reads per block/future/family batch: 128 new repair
contexts and 64 new receiving contexts before independent replay. Each context
contains sixteen cases. This count is not a runtime forecast.

The proposed principal descriptive contrast is fill-subtracted versus full
capture with writing on, for informative-record next-body recognition. Retain
common records, all six arms, both body/record endpoints, per-block and all
three injury-stratum effects, plus improvements and harms. The writing switch
and zero-memory contrasts address whether differences enter through body
feedback, outgoing records or both. Do not infer a unique mechanism from one
contrast or attach a post-hoc confirmation gate.

Before any simulation, freeze the initialization rules, finite record channel,
pairing, retained inputs and analysis. Qualify the new memory initializer on
excluded miniature cases, reject mask/label leakage and packet corruption,
reproduce the two existing arms, and independently replay all new trajectories.
Benchmark excluded full-size work and check current shared CPU/storage limits.
Use at most two single-thread workers; detach and leave unpolled if the measured
forecast exceeds ten minutes. Preserve failures and do not silently change
the original capture API, which correctly enforces R0 = V0.

A positive first-episode intervention would still need serial testing and a
separately frozen new-cohort experiment before any durability or population
claim. No candidate schedule, threshold or runtime is established by this note.
