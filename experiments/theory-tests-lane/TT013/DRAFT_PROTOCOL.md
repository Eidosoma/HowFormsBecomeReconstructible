# TT013 proposal: audit completion from the surviving record alone

Planning scope, 10 October 2026. The user asked what comes next after TT012.
The source assay `p05_recipient_only_completion_v0_1/runs/pilot_v1` is already
complete. This draft was written after reading its protocol, prediction,
configuration and technical completion status, before its aggregate performance
report. The audit target is fixed irrespective of the source result's direction.
This document does not launch a job or register a new scientific hypothesis.

TT012 inferred backup signs from the surviving record O but supplied historical
locations and magnitudes. The new rule uses only O and fixed apparatus: infer
node signs with the unchanged completion solver, identify all exactly zero O
edges on the known lattice, and fill them using the median absolute nonzero O
weight times the inferred endpoint-sign product. An all-zero record stays zero.
The full record, not merely its inferred signs, must obey the stated information
boundary. The source retains all 64 exposed failures and eight original blocks.

The proposed independent audit will:

1. Bind every source input/output and prior control to completed TT012. Preserve
   source failures and verify the prediction/freeze/outcome chronology. Reuse
   previously audited optimizer and native-reader code with explicit identities;
   execute no source scientific functions.
2. Reconstruct all 64 completion solutions and all nine records. Check exact
   zero support, scalar median including empty/even cases, preservation of every
   observed nonzero weight, deterministic sign shuffling, unchanged control
   identities, fresh injury masks and every reported edge/weight resource count.
   Check that modifying historical packets, donor records, old injury masks,
   body states, task labels or outcomes cannot affect the recipient-only record.
   Distinguish this algorithmic boundary from blinding of the full containers.
3. Verify the original-mask controls with the new contract: historical-support
   repairs 2–5 must match O. All-zero-edge repairs 6–7 can legitimately differ
   when they add edges outside the original injury. Preserve those interventions;
   do not import TT012's broader trajectory-identity check unchanged.
4. Independently replay 64 known incoming reads and 9,792 experimental/control
   contexts with byte-exact native comparisons, then independently reconstruct
   all saved-window task scores, tables, paired counts and block summaries.
   Reproduce the 20,000-resample whole-block bootstrap with seed 2026101005.
5. Retain the declared primary recipient-completion minus outgoing forecast,
   its sign rule and equal-block weighting. Report the recipient-minus-shuffled
   secondary separately: improvement over O alone does not isolate inferred
   sign placement. Preserve all eight secondary contrasts and the opposite-task
   endpoint. No positive secondary can replace a failed primary.

Qualification should exercise tiny weights, all-zero records, genuine absent
edges, counterfactual hidden inputs, scale behavior, identical shuffles, strict
task thresholds and a nontrivial failed-primary report. Benchmark the unchanged
largest block and freeze a single-thread runtime estimate before a complete
audit. Jobs forecast over 600 seconds must be persistent, detached and unpolled
after one startup check, with automatic scoring/reporting and COMPLETE/FAILED.
Never overwrite completed jobs or silently reduce scope to fit a benchmark.

Interpret resource-removal contrasts as effects along the specified sequence,
not a full factorial decomposition. Filling edges changes normalization and
connectivity; inferred signs are only one possible contributor. A positive
result supports this fixed conventional repair rule under the supplied lattice,
input locations, solver and reader. A negative result rejects this rule and
panel, not every history-free repair method. Neither direction establishes an
autonomous apparatus, irreducible historical content or a unique RDT law.

After an independent audit, a frozen new-block evaluation could test whether any
supported effect generalizes. Set practical effect and shuffled-control criteria
before new outcomes and budget power at the block level. Do not treat another
noise draw on these exposed cases as a new hypothesis holdout. The opposite-task
twin construction from TT012 remains a separate task-content design; checking
its topology does not substitute for this information-removal question.
