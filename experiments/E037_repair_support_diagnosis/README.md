# E037 — why cue-only writing cannot regrow lost connections

**Complete: retained analysis, independent checks and artifact closeout passed.**
The recovered original programs reproduced every previously reported selected
mean on all 32 E036 blocks / 512 lineages. No new trajectories ran.

Both cue-contrast policies restored **0 of 572,280** connections that became
physically available after being absent in the preceding body. Standard writing
restored **566,862 (99.05%)**, all initially weak (|weight|<=0.5). These are repeated
connection observations, not independent lineages. With strong preservation,
cue-contrast's nonzero mask exactly matched cumulative damaged copying at every
coordinate of all **8,192 lineage-boundaries**.

A previously removed cell returns with zero incident inherited weights. Paired
births/noise and local weighted reading give it identical activity under opposite
cues. Its cue difference is zero; pure difference-product capture cannot
reconnect it. Ordinary coactivity supplies weak repairs which can subsequently
strengthen. This is a structural limitation of this apparatus, not evidence that
a particular rescue policy works.

The best standard policy has a separate remaining limitation. At h16 its records
connect all outputs through nonzero edges in every case, and through strong
edges in 91.60%, while scattered both-cue success is 56.64%. Unsigned graph
connectivity is not sufficient for correct function.

The analysis retains per-block measurements, all descriptive whole-block
bootstrap intervals, source hashes, original in-memory receipts and exact code
hashes. Source scores, counts, masks, graphs, output classes, transitions and
intervals were independently checked. The figure was visually inspected.

An initial recovery wrapper failed because it invoked the unchanged support
script without the experiment root on its import path. Its failed receipt is
preserved. A continuation's compile-time indentation failure is also preserved;
no code body executed in that attempt. The successful continuation executes the
support script as a module. Original analysis code and measured arrays were
unchanged; these operational failures do not supply scientific outcomes.

[E038](../E038_weak_bridge_capture/README.md) prospectively tested cue-sensitive
capture with ordinary coactivity at exact-zero cue products and continued
weak updating. It passed both primary improvement and all nine durability
requirements: 82.03% scattered success at h16 versus 57.81% standard
preservation. A full-rewriting variant reached 89.45% as a secondary lead.
These fresh intervention results are separate from this reused-record diagnosis.
