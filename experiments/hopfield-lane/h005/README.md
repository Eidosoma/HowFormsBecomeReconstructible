# H005: present expression and continuation under a common future

The [protocol](PROTOCOL.md) compares G16 records from H003's gain-1 and gain-4
histories under an identical gain-4 future reader, complete writer, damage law
and time budget. It uses 384 prespecified pairs from the 24 development base
networks and generates eight new future branches per pair, each with 16 more
replacements. H004's confirmation cohort and verdict are unchanged.

The study completed on 11 October 2026 and **does not qualify**. Its 106
matched pairs span all 24 base networks. Terminal renewed success was
**83.46% versus 87.49%**, a gain-4-history advantage of **4.03 percentage
points** [95% interval 1.97, 6.18]. This passes the adjusted positive-direction
test but fails the frozen ten-point effect minimum. Every other decision gate
passed. Nine scientific fixtures and all **9,429 audit checks** passed;
runtime was 17 minutes 19 seconds. All four checksum manifests were verified
and the finished figure inspected. See the
[report](../runs/h005_development_v1/REPORT.md),
[summary](../runs/h005_development_v1/summary.json) and
[figure](../runs/h005_development_v1/overview.png).

Independent current success was **96.53% versus 98.11%**. Its 90% difference
interval [0.37, 2.96] points lies within the declared five-point bounds, as do
all four output-mean intervals. This finite-observer validation leaves a small
present-performance difference; the future gap alone cannot establish a
property independent of present performance.

A descriptive closeout count finds **41 of 106 matched pairs have identical
complete packets**, using the retained eligibility and packet-identity flags.
Mean signed cue association is .978 versus 1.000. Matching therefore selected
records with little remaining contrast on that descriptor. This is a lead
for a direct cue-connection perturbation study, not proof that the descriptor
explains the entire effect. Identical pairs remain in the primary cohort;
no threshold, protocol or frozen artifact was changed after seeing results.

Four new present-function readings must pass and match exactly in all four
output means for a pair to enter the primary comparison. Sixteen separate
readings then validate current expression without changing eligibility. The
match, all present data and directional forecast are sealed before any future
branch is generated. Every candidate pair is simulated, even if it does not
match, and no branch stops after failure.

Qualification requires at least 64 matched pairs across at least 16 networks,
the independent present-expression checks, and the five future contrasts in
the protocol. A favorable future difference cannot rescue inadequate matching
or unequal present performance. Means and bootstrap intervals weight base
networks equally; the eight future branches are nested within them.

Seven record arms retain renewal, equalized packets, opposite-rule donor
packets, protected copying, cumulative-loss copying, read blocking and write
blocking. Equalized packets must have exactly identical futures under the
paired tapes. Terminal function and uninterrupted function are separate
outcomes. Matching is limited to the declared finite observer; it does not
assert identical complete states or isolate the causal effect of past gain.

This is prospective development on exposed checkpoints with new future tapes.
It fits no prediction model. The source records and writing bodies are
extracted from the sealed H003 outputs; no private source, state, learned model
or result is imported. The neighboring theory lane's P02 protocol was read to
check the common-future and observer boundary. Its fitted models and code are
not used.

From the lane root:

```bash
bash run_python.sh h005/launch.py --mode benchmark
bash run_python.sh h005/launch.py --mode development
```

The default destinations are `runs/h005_benchmark_v1` and
`runs/h005_development_v1`. Existing paths are refused. An explicit `--version`
allows a separately retained technical attempt; `--benchmark` names the
completed engineering run that must match the main run's source. Each run
executes only its own frozen source snapshot and extracted inputs.

The full-block benchmark includes all eight future branches and the complete
audit. Forecasts above ten minutes run detached on one worker and one numerical
thread under the [execution policy](../../RUN_POLICY.md), with stdin closed,
PID, log and durable status. The user requests status checks. `STATUS.json`
reports the current phase; `AUDIT_PROGRESS.json` records audit progress by
block. `ENROLLMENT.json` and `FORECAST.json` preserve the pre-future boundary.

Future packets are stored as lossless ternary int8 codes; divide by 64 to
recover the exact float64 matrices used in simulation. All bodies, masks,
checkpoint readers and endpoints are retained. The final report includes every
failed gate, matched coverage, separate validation, record controls and the
unmatched cohort summary. No forms manuscript edit or release is performed.
